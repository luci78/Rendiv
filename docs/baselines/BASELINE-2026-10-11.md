# Baseline Rendiv — 2026-10-11

## Scop și metodă

Acest document fixează starea observată înainte de proiectarea sau implementarea cozii Rendiv. Este un snapshot read-only al repository-ului Rendiv, containerelor Docker și codului sursă Pithagoras/Understory. Nu descrie arhitectura țintă drept funcționalitate existentă.

Nu au fost citite fișiere `.env`, configurații persistente care pot conține credențiale, memoria Understory sau date de utilizator. Din environment-ul containerelor au fost afișate numai setările AI neconfidențiale `LLM_MODEL`, `LLM_API_BASE_URL` și `LLM_API_FORMAT`. Nu s-au făcut cereri MCP/HTTP, inferențe, mutații, teste, restarturi sau deployment. Căile host ale bind mount-urilor sunt omise din acest document pentru a nu copia identificatorul personal din path; destinațiile și tipurile mount-urilor sunt consemnate.

## Arhitectură și fluxuri existente

### Rendiv

- Repository-ul Rendiv conține documentație și reguli de proiect. La momentul baseline-ului, fișierele urmărite de Git sunt `AGENTS.md`, `docs/ARCHITECTURE.md`, `docs/DEVELOPMENT.md`, `docs/LATEST-REPORT.md`, `docs/PITHAGORAS-UNDERSTORY-ANALYSIS.md` și prezentul baseline. Nu există cod urmărit pentru o coadă, worker, API de enqueue sau integrare Home Assistant.
- Coada persistentă serială, acceptarea asincronă, prioritatea inferenței conversaționale Pithagoras și procesarea loturilor Home Assistant sunt cerințe/intenții documentate, nu comportament implementat. Prioritatea relativă între loturile din coadă este încă nedecisă.
- Containerul numit `rendiv-studio` există pe host, dar nu este dovadă că această clonă Rendiv implementează coada sau că rulează cod din repository-ul curent.

### Pithagoras și Understory

- Codul Pithagoras configurează integrarea MCP Understory cu URL implicit `http://localhost:3800/mcp`, `lifecycle: "lazy"` și `directTools: true` (`server/src/features.ts`). Setarea URL poate fi suprascrisă prin environment sau configurația MCP persistentă. Intrarea este activă numai dacă apare în configurație și adaptorul MCP este activ; configurația runtime nu a fost citită.
- Adaptorul selectat de codul Pithagoras este `pi-mcp-adapter@2.18.0` (`server/src/api/mcp.ts`). Aceasta este versiunea fixată de sursă, nu o verificare a pachetului instalat efectiv în container.
- Când este configurat, Pithagoras poate apela direct tool-urile Understory cu prefixul `understory_memory_*`. Codul nu pune aceste apeluri în coada `exclusive` folosită de unele operații pornite prin portalul Pithagoras. Acea coadă este în memorie și are alt domeniu; nu este coada Rendiv și nu acoperă apelurile MCP directe.
- Programarea Pithagoras pentru `dream` folosește timer în proces. Persistența rezultatului ultimei sesiuni nu o transformă într-un registru durabil al operațiilor MCP de scriere.
- Understory oferă MCP HTTP stateless la `/mcp`. Codul înregistrează `memory_query`, `memory_add`, `memory_update`, `memory_status` și `memory_maintain`. Query folosește agentul de citire; add/update/maintain apelează `runMutation`, care folosește unelte de scriere asupra bundle-ului.
- Răspunsul MCP pentru o mutație conține rezumatul și fișierele schimbate sau indică eșec/parțial. Codul inspectat nu expune ID durabil de job, status per mutație sau cheie de idempotency. `memory_status` este statusul bazei de cunoștințe, nu statusul unei operații.
- Ruta Understory `/api/chat` folosește toolset-ul complet care include unelte de scriere (`packages/server/src/api/chat.ts`, `packages/core/src/agent/agent.ts`). Este o altă cale potențială de mutație în afara MCP. Codul protejează `/mcp` și `/api` cu autentificare bearer numai dacă setarea serverului este configurată; starea efectivă nu a fost citită.
- Understory folosește un agent intern pentru operațiile asupra bundle-ului și trimite cererile AI la endpointul configurat. Nicio cerere nu a fost executată în audit; latența runtime nu a fost măsurată.
- În contextul Rendiv, Home Assistant este prevăzut să trimită loturi logice, iar Understory să decidă organizarea semantică. Nu s-a confirmat o integrare Home Assistant implementată sau un flux activ Home Assistant → Rendiv → Understory.

- **Understory, confirmat în environment-ul runtime Docker:** `LLM_MODEL=Qwen3.6-35B-A3B-Q5_K_M`, `LLM_API_BASE_URL=http://192.168.20.30:8080/v1`, `LLM_API_FORMAT=openai`. Sunt confirmate și `BUNDLE_ROOT=/bundle` și `PORT=3800`; acestea corespund mount-ului persistent și portului publicat.

Setările efective pot proveni din stocarea persistentă a aplicației; aceasta nu a fost inspectată. Documentele anterioare consemnează că aceeași configurație a fost furnizată de utilizator, dar nu constituie confirmarea runtime a acestui baseline.
- **Server llama.cpp:** endpointul de mai sus este confirmat ca setare trimisă containerului Understory. Accesibilitatea efectivă, răspunsul serverului și modelul încărcat în acel moment nu au fost testați. Folosirea aceluiași endpoint de către Pithagoras nu este confirmată în această verificare.

## Mount-uri, rețele, porturi și restart

Sursele host ale bind mount-urilor sunt redacționate; destinația în container, tipul și permisiunea sunt din Docker inspect.

| Container | Mount-uri (tip → destinație, acces) | Rețea | Porturi publicate | Restart |
|---|---|---|---|---|
| `ai-pithagoras` | bind → `/data` (rw); bind → `/workspaces` (rw) | `host` | Nicio mapare Docker; în `host` porturile nu sunt reflectate ca mapări Docker | `unless-stopped` |
| `ai-understory` | bind → `/bundle` (rw) | `ai-stack_default`, aliasuri Docker `ai-understory` și `understory` | `0.0.0.0:3800` → `3800/tcp` | `unless-stopped` |
| `rendiv-studio` | bind → `/workspace` (rw); bind → `/persist/.codex` (rw); bind → `/etc/ssl/certs/ca-certificates.crt` (ro) | `rendiv-config_default` | `192.168.20.100:3000` → `3000/tcp` | `unless-stopped` |

- Pithagoras folosește host networking, iar Understory este într-un bridge separat. Aliasul Understory este vizibil în `ai-stack_default`; nu există bridge comun între Understory și `rendiv-studio` (`rendiv-config_default`).
- Publicarea Understory pe `0.0.0.0:3800` înseamnă bind pe toate interfețele IPv4 ale hostului. Expunerea efectivă de la distanță depinde de rutare/firewall; nu s-a verificat.
- `unless-stopped` este politica de restart a Docker. Nu confirmă recuperarea unei mutații MCP sau existența unei cozi durabile.

## Persistență și recuperare existente

- Bind mount-urile `/data` și `/workspaces` păstrează datele Pithagoras în afara containerului; bind mount-ul `/bundle` păstrează datele Understory în afara containerului. Nu au fost inspectate fișierele din aceste mount-uri.
- Codul Pithagoras are o bază SQLite și mecanisme persistente pentru routines/scheduler; supervisorul poate marca run-uri întrerupte. Acestea sunt mecanisme cu alt scop, nu coadă de scrieri în memoria Understory.
- Codul Pithagoras are o coadă `exclusive` numai în memoria procesului pentru anumite operații inițiate prin portal. Nu este durabilă la restart și nu serializează toate tool-urile MCP directe.
- Transportul HTTP MCP Understory este stateless per cerere. Nu a fost identificat un registru persistent pentru operații `add/update/maintain`, o reluare sigură după restart sau idempotency per operație.
- În repository-ul Rendiv nu există implementare de coadă sau strategie de recuperare. Backup-ul mount-urilor, retenția datelor și rezultatul operațiilor la crash nu au fost auditate.

## Căi de scriere și ocolirea Rendiv

Căile următoare sunt confirmate în cod sau în topologia runtime ca posibile; folosirea lor efectivă depinde de configurarea și controlul accesului care nu au fost inspectate.

1. **Pithagoras → MCP Understory direct:** codul poate expune tool-urile Understory direct (`directTools: true`). Dacă MCP-ul este activ în configurația runtime, `add/update/maintain` pot modifica memoria fără Rendiv.
2. **Client de rețea → Understory `/mcp`:** portul 3800 este publicat; endpointul oferă tool-uri mutative MCP. Autentificarea efectivă și setul de clienți accesibili nu au fost confirmate.
3. **Client web/API → Understory `/api/chat`:** chat-ul folosește unelte de scriere; ruta este sub protecția bearer opțională. Activarea protecției nu a fost verificată.
4. **Acces direct la fișiere:** `/bundle` este bind mount read-write; procesele/actorii cu acces la sursa host pot edita memoria fără MCP și fără Rendiv.
5. **Procese CLI/operator:** codul Understory exportă `runMutation` și are o interfață CLI de mutație în sursă. Prezența/folosirea acesteia în imagine runtime nu a fost verificată.

Nu există acum un endpoint Rendiv de enqueue care să fie poarta unică pentru aceste scrieri.

## Timeouturi și limitări

- Codul Pithagoras fixează `pi-mcp-adapter@2.18.0`; intrarea Understory generată în `features.ts` nu declară `requestTimeoutMs`.
- Documentația anterioară consemnează 60 s ca timeout implicit raportat, iar adaptorul poate primi configurare globală sau per server. Fișierul runtime `mcp.json` și setările adaptorului nu au fost citite; timeoutul efectiv și override-urile rămân **neconfirmate**. Versiunea efectiv instalată a adaptorului nu a fost confirmată separat.
- Unele operații Understory pot dura minute conform contextului documentat anterior, însă durata operațiilor din acest runtime nu a fost măsurată. Timeoutul clientului nu este dovadă că mutația s-a oprit sau nu s-a aplicat.
- Codul verificat nu oferă status durabil per mutație, job ID ori idempotency key. Închiderea conexiunii/efectul anulării și siguranța retry-ului nu sunt confirmate.
- Codul Pithagoras nu confirmă un contor global al tuturor inferențelor către endpointul llama.cpp comun. Prioritatea conversațională Pithagoras este cerință de proiectare, nu funcție runtime confirmată; o operație Understory deja pornită nu trebuie întreruptă brutal.
- Prioritatea/echitatea între loturile viitoarei cozi este nedecisă. Home Assistant trebuie să trimită loturi logice; organizarea semantică aparține Understory.

## CONFIRMATE / NECONFIRMATE / RISC

### Confirmate

- Container-ele enumerate și ID-urile imaginilor locale, politicile Docker de restart, destinațiile mount-urilor, tipul bind, rețelele și porturile din tabele.
- Setările AI `LLM_MODEL`, `LLM_API_BASE_URL` și `LLM_API_FORMAT` furnizate containerului Understory.
- Commiturile HEAD ale checkout-urilor sursă Pithagoras și Understory, la data inspecției.
- Căile și comportamentul descrise mai sus în codul Pithagoras/Understory revizuit și documentat în analiza existentă.
- Absența unei cozi implementate în fișierele urmărite de Git ale repository-ului Rendiv la acest baseline.

### Neconfirmate

- Modelul/endpointul efectiv Pithagoras, alți clienți ai llama.cpp și încărcarea/funcționarea endpointului în momentul auditului.
- Asocierea checkout-urilor sursă Pithagoras/Understory cu imaginile Docker locale, versiunile reale ale aplicațiilor și versiunea runtime instalată a adaptorului MCP.
- Activarea intrării MCP în Pithagoras, URL-ul efectiv, timeoutul efectiv și override-urile sale, precum și setarea de autentificare Understory.
- Atingerea portului Understory prin firewall/rutare, clienții care îl pot accesa și cine folosește căile de scriere alternative.
- Backup-urile, retenția și recuperarea datelor persistente; anularea sau continuarea unei mutații la timeout/deconectare.
- O integrare Home Assistant activă sau orice flux de enqueue existent în Rendiv.

### Riscuri

- Căile MCP, `/api/chat` și accesul read-write la bundle pot permite scrieri fără coada Rendiv; portul Understory este legat pe toate interfețele IPv4 ale hostului, iar autentificarea efectivă nu a fost confirmată.
- Timeoutul sau restartul în timpul unei mutații poate lăsa efectul ambiguu. Fără status/idempotency confirmate, retry-ul poate repeta efecte.
- Prioritatea pentru conversațiile Pithagoras nu poate fi afirmată ca implementată pe baza codului actual; pornirea unei conversații după ce Understory a început poate concura pentru serverul comun.
- Bind mount-urile oferă persistență față de recrearea containerului, dar nu dovedesc backup sau recuperare a aplicației.

## Comenzi read-only pentru comparații ulterioare

Comenzile următoare evită environment-ul complet, logurile, conținutul configurațiilor și datele din memorie. Prima comandă de Docker afișează numai destinațiile mount-urilor, nu sursele host.

```sh
docker ps --format '{{.Names}}\t{{.Image}}\t{{.Status}}'
docker inspect --format 'NAME={{.Name}} IMAGE_REF={{.Config.Image}} IMAGE_ID={{.Image}} STATUS={{.State.Status}} RESTART={{.HostConfig.RestartPolicy.Name}} NETWORK_MODE={{.HostConfig.NetworkMode}} PORTS={{json .NetworkSettings.Ports}} MOUNTS={{range .Mounts}}{{.Type}}->{{.Destination}}(rw={{.RW}});{{end}} NETWORKS={{range $name,$net := .NetworkSettings.Networks}}{{$name}}(aliases={{json $net.Aliases}});{{end}}' ai-pithagoras ai-understory rendiv-studio
docker inspect --format '{{.Name}}{{range .Config.Env}}{{if or (eq (index (split . "=") 0) "LLM_MODEL") (eq (index (split . "=") 0) "LLM_API_BASE_URL") (eq (index (split . "=") 0) "LLM_API_FORMAT")}}{{printf "\n  %s" .}}{{end}}{{end}}' ai-pithagoras ai-understory
docker image inspect --format 'IMAGE={{.RepoTags}} ID={{.Id}} DIGESTS={{json .RepoDigests}} CREATED={{.Created}} VERSION={{index .Config.Labels "org.opencontainers.image.version"}} REVISION={{index .Config.Labels "org.opencontainers.image.revision"}}' ai-stack-pithagoras:latest ai-stack-understory:latest ghcr.io/thecodacus/rendiv-studio:latest
git -C ~/ai-stack/pithagoras rev-parse HEAD
git -C ~/ai-stack/understory rev-parse HEAD
git -C ~/Rendiv-project rev-parse HEAD
```

Nu rulați `docker inspect` fără format filtrat, `docker exec`, comenzi MCP, teste, inferențe sau mutații ca parte a unei comparații de baseline fără o autorizare și o evaluare separată. Nu includeți în rapoarte sursele host care conțin identificatori personali, credențiale sau conținutul memoriei.
